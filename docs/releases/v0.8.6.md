# Gilbert Codex v0.8.6

v0.8.6 is a fast official refresh on top of the v0.8.5 production release. It keeps the private official line moving with the latest product updates, the Firebase-hosted updater feed, the website download manifest, and the cloud subscription routing work already established in v0.8.5.

## Release Shape

- Version: `0.8.6`
- Product line: private official repo, `GilbertCodex-Official`
- Website download surface: `https://gilbertcodex.com/#download`
- Updater feed: Firebase Storage `releases/latest.json`
- Release source: GitHub Actions builds Windows, macOS, and Linux artifacts, then mirrors public release files into Firebase Storage on tag releases

## Included In This Refresh

- Latest app and settings updates from the official product branch
- Connector gateway updates, including Discord client secret deployment wiring
- Billing, subscription, and plan-gating refinements
- Account, provider, and connected-app UI updates
- Firebase Storage CORS policy for browser-readable website release manifests
- Existing signed updater flow using the official private-line Tauri updater key

## Expected Public Artifacts

| Platform | Download |
| --- | --- |
| Windows x64 | `Gilbert-Codex-0.8.6-x64-setup.exe` |
| macOS Apple Silicon | `Gilbert-Codex-0.8.6-macos-aarch64.dmg` |
| macOS Intel | `Gilbert-Codex-0.8.6-macos-x64.dmg` |
| Linux AppImage | `Gilbert-Codex-0.8.6-linux-x64.AppImage` |
| Linux deb | `Gilbert-Codex-0.8.6-linux-x64.deb` |

The release also publishes updater bundles, `.sig` files, `.sha256` files, `latest.json`, and `manifest.json`. The website and desktop updater both read from the Firebase Storage release feed after the tag build completes.

## Operator Checklist

1. Confirm `official/main` and tag `v0.8.6` point at the same release commit.
2. Wait for the Release workflow to finish Windows, macOS, Linux, and `publish-firebase-release-feed`.
3. Confirm Firebase Storage has `releases/latest.json`, `releases/manifest.json`, and `releases/v0.8.6/*`.
4. Open `https://gilbertcodex.com/#download` and confirm each platform button resolves to a public Firebase Storage file.
5. Install the Windows build and use the in-app updater against the published Firebase feed.

## Known Limits

- macOS artifacts can still be ad-hoc signed and unnotarized until Apple Developer signing/notarization secrets are added.
- Linux packages still need real distro smoke testing before calling Linux fully verified.
